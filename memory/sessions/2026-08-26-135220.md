## Key design decisions

**Milestone-as-set (the critical insight):** Three SoR milestones (validated, preprocessed, processed) are an unordered SET of facts, not a state sequence. `MilestoneRecord` uses MongoDB `$ifNull` in a pipeline update for first-write-wins idempotency. Terminal state is derived from the accumulated set: any-fail → FAILED; all-pass → SETTLED; else → NOOP. This means out-of-order arrivals always produce the correct terminal state.

**Single-document atomicity:** Each fulfillment is one MongoDB document with embedded `outbox[]` array. State change + outbox entry commit in a single `findOneAndUpdate` pipeline update (`$concatArrays`) — no multi-document transactions needed.

**Graph model (`fulfillment-lifecycle.json`):** DB-agnostic, identical in shape to the Postgres version. Key nodes:
- `await-sor`: JUMP MODE — IF progress=waiting THEN suspend ELSE sor-outcome. No drawn edge to suspend; re-evaluated on each resume. This is the milestone barrier wait loop.
- `validated` (Suspensible): edge mode, suspends at first checkpoint (VALIDATED→SCHEDULED)
- `dispatch` (Suspensible): edge mode, suspends at second checkpoint (SCHEDULED→DISPATCHED)
- `graph.suspend` / `graph.resume` use Redis (minigraph-state-redis) for graph state; MongoDB holds business data

**Flow patterns:**
- `steward-ack-flow`: record milestone → graph.executor → v1.steward.record.status. Maps `model.derived_state` (from recorder, not graph output) to `to_state` — avoids "Missing to_state" on graph suspension. No exception handler (Kafka-facing, failures dead-letter).
- `steward-request-flow`: v1.fulfillment.create → graph.executor (fresh run) → v1.steward.record.status
- `steward-tick-flow`: graph.executor (resume) → v1.sor.dispatch → v1.steward.record.status

**Self-transition guard:** `StewardRecordStatus` filter uses `{lifecycle_state: {$ne: to_state}}` — late duplicate acks can't rewrite a completed fulfillment.

**Outbox relay:** Finds documents with `{outbox: {$elemMatch: {sent_at: null}}}`, publishes each entry, marks with `$set "outbox.$[e].sent_at"` + arrayFilters.

**Demo mode:** All schedulers check `Demo.suppressed(input)`. REST admin endpoints pass `text(manual) -> trigger`.
